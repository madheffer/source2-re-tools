# source2-re-tools

Reverse-engineering tools and notes for Source 2 and Counter-Strike 2: the resource compiler and the map tools, and
the game itself (server.dll, client.dll and the engine DLLs under them). What's here is read from Valve's own
binaries, with every address tied to the DLL build it was read from, so a port can be checked against the
original and kept honest across CS2 updates.

## What's here

| Path | What |
|---|---|
| [tools/re/](tools/re/) | The compiler-side tooling: Ghidra / ReVa helpers (`reva_serve.py`, `reva_call.py`, `batch_decompile.py`), offline PE scanners, Frida capture scripts (`capture_*.py`), Unicorn and native oracles (tier0's maths, KV3, cubemaps, hull casts, shader dictionaries), the patch tools (`patch_check.py`, `build_diff.py`) and the per-build name tables in `tools/re/names/` |
| [tools/re/game/](tools/re/game/README.md) | The game-side helpers: standalone DLL scanners for classes, vtables, calls, fields, strings, ConVars, schema and protobuf, and Unicorn oracles that run client.dll / tier0 code on random inputs |
| [tools/ghidra_scripts/](tools/ghidra_scripts/) | Ghidra scripts (naming by asserts and log strings, dumps by string / RTTI / callers, signatures) |
| [docs/ADDRESSES.md](docs/ADDRESSES.md) | The compiler-side addresses per module and DLL build (resourcecompiler, vphysics2, physicsbuilder, meshsystem, vrad3, navsystem, ...), generated by `tools/re/address_doc.py` from `tools/re/names/make_manual.py` |
| [docs/game/](docs/game/README.md) | The game-side traces: 115 subsystems of CS2's server.dll and client.dll (movement, weapons and shots, grenades, damage, the round, entity I/O, the HUD, physics, rendering, the menus), each as tables of functions, field offsets and constants, then sum orders; plus the general helpers' tables |
| [docs/csgo/](docs/csgo/README.md) | CS:GO legacy (32-bit) notes: triggers, VScript, effects, the BSP bake. Not CS2 |
| [docs/crazykart/](docs/crazykart/README.md) | ze_crazykart's physics on CS:GO's legacy vphysics.dll (IVP): the kart, contacts, impacts, mindists, shadows. Not CS2 |
| [tools/docs_numbers.py](tools/docs_numbers.py) | Lists the addresses, offsets and numbers a doc edit dropped (`--git HEAD <paths>`): run it before committing a rewrite |

## Setup

Python 3.10+ with `pip install pefile capstone numpy unicorn` covers the offline scanners and the oracles; the
Frida captures need `frida`, the Ghidra tools Ghidra 12 with pyghidra and the ReVa extension. Nothing is tied to one
machine; each install is found from an environment variable (`tools/re/paths.py`):

| Variable | Default | What |
|---|---|---|
| `CS2_DIR` | found through Steam (the registry's Steam path and its `libraryfolders.vdf`) | the Counter-Strike 2 install, the folder that holds `game/` |
| `S2C_BINARIES` | `tools/re/binaries/` | your archived DLL builds, `<dll>_<yyyymmdd>.dll` (not in git: Valve's files) |
| `S2C_GHIDRA_ROOT` | `.tools/` in the clone | Ghidra, its `ghidra_projects/` and the `reva-venv/` |
| `GHIDRA_INSTALL_DIR` | `$S2C_GHIDRA_ROOT/ghidra_12.1.3_PUBLIC` | Ghidra itself |

The tools never ship Valve's binaries: copy the builds you analyse into `tools/re/binaries/` yourself (the address
pages name each build's file and date).

## Working rules

- An address means nothing without its build: all the DLLs load at 0x180000000. Record every address with the
  module and build it was read from: the compiler's in `tools/re/names/make_manual.py` (then run
  `tools/re/address_doc.py`), the game's in the subsystem's page under `docs/game/` (tables: functions, fields, constants; then the order and sum orders; no prose).
- After a CS2 update run `tools/re/patch_check.py`, then `tools/re/build_diff.py`: every recorded address is found
  again (identical, relocated, moved, changed or missing).
- Sum orders and constants come from the disassembly, not the decompiler (it drops register arguments and gets
  maxss / minss with NaN wrong).
- Write down what you reverse in the same change: addresses, what each function does, offsets, vtable slots,
  constants, and what's still unread.

## Where it came from

The compiler-side tools were split out of the Source 2 resource compiler port (rc-standalone, cs2-map-compiler)
with their history on 2026-11-15; those repos still carry a copy of `tools/re` while their oracle tests call the
scripts by path. The game-side tools and traces came from cs2web (CS2's game modes in the browser) on 2026-11-21.
New RE work, of either side, goes here.
