# The input dispatch and the classes' input tables (2026-11-10)

server_20261105.dll. Read with capstone (tools/re/game/disasm.py) and Ghidra's ReVa (headless, over HTTP). The port:
sim/src/game/inputs.rs (the lookup), sim/src/game/input_table.rs (generated by tools/re/game/inputs.py), web/src/cs2web/world/cs2-inputs.js,
web/src/world/entities/accept.js (CS2Fixes' detour, then the lookup), called first by engine.input.

## AcceptInput and the dispatch

- **AcceptInput** (1813a8ed0: identity, input name, activator, caller, value): the name is pooled (18137d560 on the
  entity system's string pool, DAT_182331b00 + 0x1f50), the value copied into a variant, then **1813ac4d0** with the
  identity's +0x10.
- **The string pool** (180535520): MurmurHash2 with seed 0x31415926 over the **ASCII-lower-cased** text (18054ba10:
  CBufferString::ToLowerFast, then the hash), the bucket compared with `_V_strnicmp_fast` and the length (180524c70).
  So an input name is matched **case-insensitively**, by pooled pointer: `trigger` = `Trigger` = `TRIGGER`.
- **1813ac4d0** (rcx = { +0 the entity, +8 its CEntityClass }): 
  1. **181373b60**(class, entity, &name, activator, caller, value, output id): the class's input object at
     **class+0x28**, its vfn 1 (+0x08) with the pooled name: true -> handled (returns 2). Else the base class:
     `class+0x60` (the class info of the base) `+0x18` (its CEntityClass), recursively. 0 when no class in the chain
     has it.
  2. Not found: the entity's **vfn 0x88** (CBaseEntity's 180cdfd30: the component at +0x4a0, 180f10640, which looks
     the name up in the entity's Pulse graph and runs it). ZE's maps have no Pulse graphs: not ported.
  3. Not found: the script path after 1813ac5db (io-targets.md read it as a script's `Input<name>`; its calls
     through the scripting VM's vtable, +0x120 / +0x108 / +0xa8 / +0xb8, are not followed here). No scripts in ZE.
  4. Handled: the entity system's input listeners (+0xc20, count +0xc18). Not handled: "unhandled input" logs.
- **The class's sorted table** (181373eb0, run per class by the entity system's init 181385ea0 from its class
  dictionary +0xa98): the input object's entries (`[class+0x28]+0xe0` count, `+0xe8` 0x20-byte entries, the name at
  +0) pooled (181373c30: 18137d560 per name, a linear check for a duplicate, then append { pooled name, entry }) into
  class+0xe8 / +0xf0, then sorted by pooled pointer (181373630, an introsort) so the lookup can bisect.

## Where each class's inputs come from: the entity-API bindings

A class's inputs are its **"&lt;Class&gt;_API::&lt;Input&gt;" bindings** (the same records Pulse and cs_script call): 0x50-byte
records in .data, one class's in a row:

| Offset | What |
|---|---|
| +0x00 | "CLogicRelay_API::Trigger": the input's name is the text after `::` |
| +0x08 | display name ("Trigger", "Kill Hierarchy") |
| +0x10 | description |
| +0x18, +0x20 | the parameter / return type getters |
| +0x28, +0x30 | metadata count, metadata (e.g. MPulseFunctionHiddenInTool) |
| +0x38 | flags (0x10100; 0x200010100 with bit 33 on the hidden-in-tool ones) |
| +0x48 | the handler |

Checked against what earlier traces found by other routes: CLogicRelay_API::CancelPending's handler is **180c40120**
(io-queue.md's CancelPending, found from CancelEvents' callers); CBaseEntity_API::Kill's is 180cc4dd0 -> InputKill
180cfce50 and KillHierarchy's 180cc4e40 (scene-node.md); **CBaseEntity_SharedAPI::AddOutput**'s 1803a9110 calls
1813aa560, the AddOutput parser io-targets.md traced from its "bad string" message. CBaseEntity's table also holds
the other two `_SharedAPI` records (SetScale, IsMotionEnabled). Getters (GetName, GetAbsOrigin, ...) are in the
tables too: as inputs they do nothing a map sees.

**Not inputs** (the dead ends of this session, for the next reader): the **datamaps** (class info +0x30; CBaseEntity's
0x181e25d40, 34 entries, filled at run time by 180cd8650; CPointEntity's 0x181daae88) hold keyfields only (0x38-byte
typedescriptions: +0 type, +8 field name, +0x10 offset, +0x18 flags, +0x20 the key name), read by the keyvalue
unserializer 181380400 ("IsFieldDescUsedByKeysOrIO"); the **VScript descriptors** (CEntityClass+0: 180600170 for
CBaseEntity, ScriptInputKill etc.; 1806a94c0 for logic_relay's ScriptTrigger) and the **Lua bindings** (18020a7d0)
are script APIs. MurmurHash tokens of input names don't appear in the code: the pool's pointers are compared.

## The class chain and the designer names

- **The entity class** (static, e.g. logic_relay's at 0x1820db7e0, built by its constructor 1800853f0; linked into
  DAT_182331a08 by +0x108 and registered by CEntitySystem::RegisterEntityClass 18138abb0): +0x00 the VScript
  descriptor, +0x28 the input object (set at run time), +0x58 the class info, +0x60 the base's class info, +0x68 the
  pooled class name (181375dd0), +0x70 flags inherited from the bases (181375dd0).
- **The class info** (logic_relay's 0x1820db798): +0x00 designer name, +0x08 class name, +0x18 its entity class, +0x20 the
  base's class info, +0x28 the schema binding (0x181dee5f0), +0x30 the datamap (0x181e20180).
- **The schema binding** (SchemaClassInfoData, CBaseEntity's 0x181de0270): +0x08 name, +0x20 size (u32) and field
  count, +0x28 fields (0x20 each: name, type, offset, ...; tools/re/game/schema.py), +0x38 the base list ({ u32 offset,
  binding* }), +0x40 the datamap. The chains here come from the bindings' first base: logic_relay = CLogicRelay >
  CLogicalEntity > CServerOnlyEntity > CBaseEntity > CEntityInstance; prop_dynamic = CDynamicProp > CBreakableProp >
  CBaseProp > CBaseAnimGraph > CBaseModelEntity > CBaseEntity > CEntityInstance.
- **Designer names**: the constructor stores the designer name and the class name into the class info's +0 and +8
  (`lea r, [name]; mov qword ptr [rip + X], r`: func_button at 1806198fd into 0x18208f300 / 0x18208f308). 493 pairs;
  info_particle_system's (constructor 1800d83f0) stores CParticleSystem from rbp on a branch (1800d85a8), added by hand.

## What it changes in ZE (web/server/cs2web/dev/input-census.mjs)

Every connection on the four baked maps, its targets' classes against the tables: before, engine.js's generic
switch took Enable / Disable / Toggle / Lock / Unlock / CancelPending and others on any entity. CS2 doesn't:
dark souls sends point_template Enable / Disable, func_physbox Enable, CancelPending to math_counter / logic_case /
logic_branch / trigger_hurt / prop_dynamic / point_template, Unlock to filters and a point_worldtext, Start / Stop to
info_targets, SetDamage to trigger_multiples sharing a trigger_hurt's name; RE3 SetUnbreakable to a rotating door,
PickRandom and StopSound to a relay / case, Enable/DisableCameraAll to relays that aren't CS2Fixes' tagged
viewcontrols; hold_em Open to a trigger_once sharing a door's name. All of these now do nothing, as in CS2.

## CLogicCase InValue (2026-11-12)

`CLogicCase_API::InValue` (180e11760; inputs.py lists PickRandom 180e12060, PickRandomShuffle 180e123d0,
ResetShuffle 180e12770): the parameter is a string (181389200 interns it; empty is null, compared as ""). The 32
case strings sit at +0x4a8 (8 bytes each); each non-null one is compared with `V_stricmp_fast`; the first equal
one fires its output (+0x5d0 + 0x18 x index, 1802a66e0 with the input's activator and the entity), and with no match
OnDefault (+0x8d0, 180e3e980) fires with the string as its value. No number parse anywhere: "0.0" is not "0".
The maps made for CS2 therefore write a counter-fed case as "0.0", "1.0" (ze_dark_souls: every one of its 50
logic_cases; its ending's overrides "0.0" / "1.0" match its cases "0.0" / "1.0"): a float value arrives as that text
(engine.js outputText, a stand-in until the conversion is read).
Unread: how the dispatch (1813ac4d0) turns a float output's value into this string (a math_counter's OnGetValue
wired to InValue). Port: classes/logic.js.
